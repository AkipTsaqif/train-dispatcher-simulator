# Phase 8 — Drawn-extent track topology (terminating switches + throat journeys)

## Goal

Make the generated Jatinegara layout match the drawing's true track counts —
**6 tracks at each map boundary, 8 through the platform area** — instead of the
current first cut's 8 full-width lines to both edges. Requires (a) compiler
support for **terminating switches** (a junction where a track ends and the
only exit is the branch), (b) regenerating the topology at the **drawn
extents**, and (c) re-authoring the stub journeys within their reachable
tracks. **Depends on the completed Phases 0–7 + the Jatinegara generator.**

## General / non-technical summary

The drawing's upper platform tracks (5–8) do not run to both map edges: they
end at junctions and trains leave them by diving through the crossovers. The
first cut extended every line to both edges because our switch model needs a
"through" direction at every junction. This phase teaches the model a
**terminating switch** — a track end where the only onward move is the branch —
so the tracks can end exactly where the drawing ends them, and the trains on
those stubs genuinely exit through the throat.

## Current-state analysis

- The Jatinegara topology (`app/topologies/jatinegara.ts`, generated by
  `scripts/gen-jatinegara.py`) runs all 8 lines full-width [32,1120] — the
  drawing has 6 tracks reaching each boundary (y=496/464/432/400 plus the
  y=336/304 west approaches and the y=368/336 east fragments), 8 through the
  platform area, and 4 genuine stub ends (platforms 5,6,8 end at junctions;
  platform 7 ends east at 688; the east-throat fragments AP/AM/AC/Y/AB are
  short stubs of their own).
- The compiler requires every switch to have **3 distinct ports**
  (`Switch X has duplicate ports`) — a stub-end junction (the track + one
  diagonal = 2 edges) cannot be a switch today, which forced the full-width
  workaround.
- `resolveNode` treats "no open straight exit" as `offmap` (the train leaves
  the map) rather than `blocked` (the train waits) — wrong at a terminating
  switch.
- The route search treats a closed terminating switch as a boundary route end
  (`ke ujung`) — the auto route set would clear a signal "to the stub end"
  instead of throwing the branch and routing through the throat.
- The journey model keeps fixed-Y legs; the boundary stops (JNG-W/JNG-E at
  x=40/1080) are unreachable on the stub lines, so the stub journeys must be
  re-authored within each stub's reachable extent.

## Technical design

### 8.1 Terminating switches (compiler)

Allow a switch whose `normal` port equals its `common` port: the through axis
degenerates to a single edge and the only onward exit is `reversed` (the
branch). Semantics:

- a train arriving from the track diverts onto the branch when reversed, and
  **waits (blocked)** when normal — the straight "exit" does not exist;
- a train arriving from the branch proceeds onto the track when reversed
  (came-from-branch, unchanged).

Changes:

1. `topology.ts` switch validation: relax the duplicate-port check to allow
   `common === normal` (the terminating case); keep all other port rules.
2. The GNode exit build: skip pushing the `normal`-port exit when it equals
   the `common` exit (no duplicate exits to the same neighbor).
3. `resolveNode` (train-engine): when a terminating switch offers no open
   non-reversing exit, return `{ blocked: true }` (wait) instead of
   `{ offmap: true }` (leave). `offmap` stays reserved for the genuine map
   boundary.
4. `route-search.ts` `openExits`/dead-end handling: at a terminating switch
   with the branch closed, do **not** emit a boundary route (it is a dead
   junction, not an open line); the search must either find the branch (with
   its point move) or no route.
5. `walkRoute` (component): the terminating switch is naturally handled by the
   existing "berakhir di P…" logic; verify the far-switch rejoin when a
   terminating switch is the far node of a branch path.

Bekasi has no terminating switches → byte-identical baseline.

### 8.2 Regenerate the topology at the drawn extents

Update `scripts/gen-jatinegara.py`:

- stub tracks at their drawn extents: t5 (y=368) 336→528, t6 (y=336) 32→592,
  t7 (y=304) 32→688, t8 (y=272) 224→528; the full lines t1–t4 stay [32,1120];
- the east-throat fragments as their own short stub mains: AP (1040→1120,
  y=368), AM (1008→1120, y=336), AC (752→976, y=368), Y (624→656, y=368),
  AB (688→720, y=336);
- **terminating switches** at every stub-end junction (~10: 336,368 / 528,368 /
  592,336 / 688,304 / 528,272 / 656,368 / 752,368 / 688,336 / 1040,368 /
  1008,336) — common===normal = the stub edge, reversed = the diagonal;
- per-line boundary stops at each stub's reachable extent (e.g. t5: west 340,
  east 520) so the stub journeys stay within their tracks;
- signals/blocks: exit signals open at their track's end (legacyOpenEnd); the
  exact throat block boundaries remain a documented approximation.

### 8.3 Re-author the stub journeys

The stub lines' journeys use stops within their own extents (e.g. a westbound
t5 train: JNG-E5(520) → JNG(416) → JNG-W5(340)); a train reaching a stub end
waits at the terminating switch until the player throws the branch + clears
the exit signal — the intended interactive behavior. The full lines t1–t4 keep
their existing journeys.

## Steps

1. Compiler: terminating-switch support (validation + GNode dedupe +
   `resolveNode` blocked + route-search dead-end). Add a terminating-switch
   case to a probe/verifier (e.g. the ladder or a new mini-fixture).
2. Bekasi baseline byte-identical; all existing gates pass.
3. Regenerate `jatinegara.ts` at the drawn extents; update the map/scenario/
   dispatch stops; re-run the compiler to fix validation fallout.
4. Update `verify-jatinegara` (new counts; assert the stub extents, the
   terminating switches, and that a platform-5 exit route now dives through
   the throat crossovers instead of running a straight continuation).
5. Interactive smoke: `/jng` — clearing XE5/XE6 must throw the throat
   crossovers (the drawn dive) rather than the invented straight.
6. Gates + STATUS update + commit.

## Acceptance criteria

- [ ] The layout renders with 6 tracks at each map boundary, 8 through the
      platform area, and the stubs ending where the drawing ends them (no
      invented continuations).
- [ ] Terminating switches compile; trains wait at a closed stub end and
      divert when the branch is thrown.
- [ ] A stub-line exit signal's auto route set throws the drawn throat
      crossovers (verified live at `/jng` + in verify-jatinegara).
- [ ] Stub journeys run within their reachable tracks; full-line journeys
      unchanged.
- [ ] Bekasi baseline byte-identical; `tsc`/`build`/`test:e2e` and all
      verifiers + probes pass.

## Open assumptions

- Throat block boundaries stay approximate: each signal's section opens at its
  own track's end (the section does not follow the dive yet).
- The journey model keeps fixed-Y legs; a train whose itinerary would cross
  lines mid-journey is still out of scope (the stub journeys are authored to
  stay on one track).
- The east-throat fragments (AP/AM/AC/Y/AB) are modeled as short stub mains,
  not part of the numbered platform tracks.

## Out of scope

- True journey-through-junction routing (an itinerary that changes lines
  between stops).
- Exact block signalling through the throat.
- A real Jatinegara timetable.
- The track-identity questions (5W = platform 6 etc.) — resolved by the
  drawing's extents, not by renumbering.
